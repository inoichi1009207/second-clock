## 为什么叫「第二时钟」

一瓶印着「2027 年到期」的多剂量滴眼液,今天开封之后,按说明书或《中国药典》
对眼用制剂的通则,可用期限可能只剩 4 周。

药盒上的日期是**第一个时钟**,开封后的期限是**第二个**——
而第二个通常没有地方替你倒计时。

这个项目做的就是:记录两个日期,提醒**更早到来的**那个停用日。

---

## 真正难的部分:不让模型的猜测变成事实

倒计时本身不难。难的是拍照识别环节——**不能让视觉模型猜错的药名和日期悄悄写成事实**。

在提示词里补反例之后错误仍会复现,所以本项目**没有把提示词或模型自报的置信度当成安全边界**,
而是把自动化限制在三层检查里:

1. **双厂商独立交叉验证。** 同一张照片分别交给百炼 `qwen-vl-plus` 与智谱 `glm-4.6v`,
   两边互不知道对方答案。都返回时只比对药名,**有差异就取消药库预填**;
   第二家超时或失败时,界面明确标为「仅一个模型」,不声称已经交叉核对过。
   > 只有**完全相同**才算一致——哪怕只差剂型或「复方」二字也判分歧,
   > 因为阿莫西林和阿莫西林克拉维酸钾是两种药。

2. **印刷有效期永不自动落账。** 模型识别出的包装印刷有效期一律只作「待确认」候选
   (代码层只写 `proposedExpiry`,永不直接写 `expiry`),用户点确认才落账。
   药库匹配出的开封后可用天数仍会预填,但标明来源、可修改。

3. **证据必须能被代码核对。** 模型必须交出**逐字证据**与**包装语种**,由代码校验:
   包装语种不是中文、证据里却出现汉字(那段证据不可能是抄来的),
   或它声称的年份根本不在证据原文里 ⇒ 丢弃这个日期。
   > 这一层是**一致性检查**——证据同样出自那个模型,不能算独立佐证。这一点如实标注。

## 功能

- **内置 1832 条**家庭药箱相关条目(药品、消毒用品与部分健康用品)+ **23 条剂型参考规则**,
  配常见商品名/别名。手动录入、药库匹配、计时与提醒**可离线使用**;
  拍照识别与联网查询需要网络。
- **拍药盒识别**:一次最多 4 张,识别通用名/商品名/规格/剂型/印刷有效期,
  识别完自动去内置药库带出开封期限并预填。
- **同名多剂型不猜**:一个商品名常同时覆盖几个剂型,而它们的开封期限可以差得很远
  (「希刻劳」既是干混悬剂又是胶囊,前者冲配后冷藏 14 天、后者按印刷效期常温)。
  全库有 **27 个**这样的名字。命中多条且答案不一致时**一律不预填**,
  就地列出剂型按钮让用户照药盒点一个——「剂型」字段平时选填,只在这一刻变必填。
- **查不到时不装懂**:可联网查询;仍查不到时明确提示
  「查不到不等于没有期限,请以说明书为准或咨询药师」。
- **到期标色**:打开页面时剩余 7 天转黄、剩余 3 天转红,今天到期或已过期时顶部显示红色横幅。
  可按「使用人」标签筛选,可记录冷藏/冷冻等储存条件。
- **1744 条附储存或使用注意事项**,仅在药名**精确命中**时随卡片显示
  (模糊命中本身带着不确定性,不该用确定的口吻转述安全提醒)。

**不提供**:系统推送、多人共享、储存温度监测。

### 隐私

药品记录**仅保存在本机浏览器** `localStorage`,无需注册。
拍照识别时所选照片会分别发送给阿里云百炼与智谱(两家各识别一次);
联网查询时产品名称会发送至智谱;提交药库反馈时产品名称与补充说明会发送至本站服务器。

## 技术栈

| | |
|---|---|
| 形态 | **单个 HTML 文件**,约 805 KB,CSS / JS / 药库数据全部内联 |
| 前端依赖 | **零**。无框架、无构建产物依赖、无 CDN 引用 |
| 后端 | 一个零依赖 Node 脚本(`deploy/proxy.mjs`,只用 Node 内置模块),作 API 反代 |
| 运行时 | Node 22(服务器侧)。**浏览器侧不需要任何运行时** |
| 数据库 | 无。药库内联在页面里,用户记录存浏览器 `localStorage` |
| 部署 | nginx 静态托管 + systemd 托管反代进程 |

```
浏览器
  │
  │  静态页(HTML/CSS/JS 全在一个文件里,药库内联,断网可用)
  ├─────────────────────────────► nginx ──► /var/www/2c.klinik.ren/index.html
  │                                          manual.html
  │
  │  /api/*(只有主动点「拍照识别」「联网查询」「提交反馈」时才发生)
  └─────────────────────────────► nginx ──proxy_pass──► 127.0.0.1:8791
                                                            │  proxy.mjs
                                                            │  (systemd 服务 2c-proxy)
                                                            ├─► 百炼 qwen-vl-plus  拍照识别
                                                            ├─► 智谱 glm-4.6v      交叉核对
                                                            ├─► 智谱 web_search    联网查询
                                                            └─► feedback.jsonl
```

**前端不持有任何密钥。** Key 只活在服务器上 `2c-proxy` 进程的环境变量里,
由它注入 `Authorization` 头;浏览器只看得到 `/api/...` 这样的同源路径。

## 本地跑

**不需要构建,不需要装依赖。** 双击 `index.html` 即可:
手动填写、药库搜索、倒计时、按人筛选、时间模拟全部可用。

拍照识别与联网查询会提示未配置——因为**源文件里的 `LOCAL_DEBUG_API_KEY` 是空的**
(见下面「凭据纪律」)。要在 `file://` 下调试识别链路,临时把自己的智谱 Key 填进去,
**用完清空,不要提交**。

部署版构建:

```bash
node deploy/build.mjs        # 产物写到 deploy/dist/
```

构建脚本会做出口断言(含「产物内不含任何凭据」),任何一条不过就不落盘。

### 改代码时的三个既有约定

代码注释里都写了,改动前先读那段注释:

- 渲染一律走 `textContent` / `createElement`,**不用 `innerHTML`**
- **守卫装在被调用的函数内部**,不是调用处——装调用处的闸换个入口就绕过去了
- 识别出的有效期一律只写 `proposedExpiry`,**永不直接落 `expiry`**,必须人工确认

---

## 凭据纪律

- **仓库内不含任何 Key。** `index.html` 的 `LOCAL_DEBUG_API_KEY` 常量值为空字符串。
- 服务端 Key(`ZHIPU_API_KEY` / `BAILIAN_API_KEY`)只经 `/etc/2c-proxy/env` 注入,
  `proxy.mjs` 缺 Key 直接 **fail-closed 退出**,绝不静默降级为无鉴权转发。
- 部署前跑 `node deploy/build.mjs`,它会硬校验产物不含凭据。

## 已知的不确定性(登记在案,不是 bug)

- 器械类 125 个「别名」是口语俗称(额温枪/验孕棒/暖宝宝),**未经联网核实**;
  判定依据是「风险性质不同」而非「已核实」。
- 混合包装条目(同品种既有铝塑板又有瓶装)按更保守的瓶装口径给值,说明里写明两种情况
  ——这是一个字段表达两套规则的折中,不是精确答案。
- **相当一部分开封期限取自剂型通用值而非说明书原文**,均已在 `open_note` 标注「参考值」。
- 全库 27 个商品名同时覆盖多个剂型且期限不同,靠界面消歧兜住(不预填 + 剂型按钮)。

内置期限整理自公开药品说明书与《中国药典》2020 年版相关通则;
无法逐条核到说明书原文的项目只标为「参考值」。

## 开发过程里最值得看的几条

完整七条(含作者自己犯的那次)在 [`making.html`](https://2c.klinik.ren/making.html)。

- **守卫必须覆盖所有入口,也要覆盖异步等待期。** 闸都在,多点一下就绕过去了
  ——后来把可信度判断下沉进预填函数本身。
- **我自己用正则批量改医疗数据,错了 12/19。** 「干粉常温保存;配制后冷藏」被正则匹配到
  「常温」二字,于是追加了一句意思正好相反的话。
  正则读得到字符,读不到那句话在讲哪个阶段。
  **批量生成的东西必须过一道独立的核对,包括我自己批量生成的东西。**
- **归一化在容错的同时也在制造碰撞。** 新建的「口服补液盐散(I/II)」去掉括号与斜杠后
  **正好等于** `III`,两条撞成同一个键。改名成「(I型或II型)」才躲开。

## 使用边界

> **本作品只根据用户录入的日期与参考规则做时间提醒,
> 不判断药品质量、疗效或是否变质,也不构成用药建议。**
>
> 具体期限与储存要求以该产品说明书、包装标识及药师/医师意见为准;
> 包装破损、储存异常或性状变化时,不应仅依据倒计时继续使用。
